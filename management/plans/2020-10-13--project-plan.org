* Project plan

** PG.NET

   The purpose of this project is to add support to the .NET languages (C# and
   F#) to Postgres.

   For now, several capabilities were already added, such as:
   - Simple data types (int, float, boolean) support for C#;
   - String and unicode characters support for C#;
   - Integer (32-bits) support for F#;

   However, there are still some capabilities missing, such as:
   - Composite types for F# and C#;
   - Containers for F# (e.g. SQL Arrays);
   - Trigger support for C# and F#
   - Extend simple data type support and string for F#;
   - Fixes into debian package configuration;

    So, the plan for this section of the project is to add such capabilities and
    prepare the .NET extension for the benchmarks described below.

** Other Languages

   The purpose of this group of tasks is to make sure that every language has
   the same capabilities of the .NET implementation and that we can compare its
   performance in a repeatable way.

   Reference languages:
   - Java
   - Lua
   - R
   - Perl
   - PgSQL
   - Python
   - TCL
   - sh
   - Javascript

   Roadmap:
   1. Setup all available languages;
      - Estimate: ~1 man-day~.
   2. Start benchmarking setup;
      - Estimate: ~2 man-days~.
   3. Migrate Python and Javascript test cases;
      - Estimate: ~3 man-days~.
   4. Execute first benchmarking run and verify results;
      - Estimate: ~2 man-days~.
   5. Improve benchmarking tool;
      - Estimate: ~2 man-days~.
   6. Migrate more test cases (PgSQL, Lua, Perl, Java);
      - Estimate: ~6 man-days~.
   7. Execute another benchmarking run and verify results.
      - Estimate: ~2 man-day~.

*** TODO Benchmarking setup

    Aims to define and create the infrastructure that will measure the
    performance of each operation.

    At this point, it is very important that the benchmarking infrastructure has
    small impact in the measurements and that the measurements are easily
    reproducible.

    Expected Metrics:
    - Time to perform each operation;
    - Resources usage;
      - CPU, Memory, DB Memory.
    - Standard deviation of measurements;
    - Correctness.
